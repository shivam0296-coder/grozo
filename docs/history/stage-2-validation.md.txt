## Files, decisions and maturity

Stage 1 architecture, SQL draft, API contracts and working commerce code were read and preserved. [ADR 0002](decisions/0002-stage-2-development-interfaces.md) records the local development boundary. Updated sources include the React customer/admin apps, Kotlin customer/rider/core modules, shared fixture/client/UI packages, locks and dependency verification, tests, notices, packaging helpers and documentation. The delivered ZIP manifest is the authoritative file/hash inventory.

The website/admin are development prototypes. Native apps are compiled prototypes. Browser local storage and each native Room database are independent; there is no backend or cross-app order synchronization. Typed HTTP adapters preserve the contract boundary and fail closed when unconfigured. Release configuration disables fixture mode. No real integration is represented as live. See [status](status.md) and the [completed/pending checklist](stage-2-features.md).

GROZO is not a Git repository: there is no commit, branch or remote. No neighboring research-project source was modified. The original Stage 1 README/status/validation remain under docs/history as historical text.

## Resources, budget and effects

The owner explicitly approved minimal Android toolchain acquisition capped at 3 GB downloads and 6 GB disk, without an emulator or paid service. Official checksummed JDK, command-line tools, Gradle and initial SDK archives total approximately 0.63 GB. Maven artifact files measured approximately 0.48 GB; a corrected SDK platform, retry fragments, metadata and npm add overhead. The conservative transfer estimate is 1.3–1.6 GB; exact wire bytes were not profiled. Downloads stopped within the approved estimate.

The [disk checkpoint](../reports/resource-usage.json) totals 4,771,056,228 bytes (4.77 GB) across toolchains, caches, installed web packages and Android build directories. It includes retained download archives. The two externally copied APKs add about 41 MB; the small source/report archive adds little overhead. This remains below 6 GB. These local toolchains/caches/build intermediates are excluded from the source ZIP.

Work used CPU compilation and local browser testing, with no GPU, training, emulator, paid API, cloud deployment or publication. Official dependency repositories received normal package/download requests; no real customer/rider records, keys, payment data or precise locations were submitted. Only clearly labelled fictional fixtures are included. No external AI integration is present.

The original all-rights-reserved project license remains unchanged. Original SVG grocery illustrations avoid acquired product photographs. Third-party code retains its own notices/licenses; vendor JDK/SDK distributions and private debug keystores are excluded. This record is not a legal audit or a penetration test.

## Resolved issues and skipped checks

Resolved: Windows symlink limits, package-age policy rejection, resumable download stalls, Gradle wrapper availability probe, SDK package-directory identity, stale Kotlin daemon temporary path, JSX/type errors, mobile table overflow and drawer focus, and repeated React root creation during hot updates. The final structural/type/build/unit/workflow checks listed above pass. Detailed Android setup warnings are in the [build report](stage-2-build.md).

Not performed: native device/emulator UI execution or screenshots, release signing/AAB/Play publication, Android dependency vulnerability scan, full accessibility audit, load/soak/performance testing, PostgreSQL migration execution, backend authentication/RBAC/ownership/concurrency tests, provider sandbox tests, live OTP/payment/refund/Maps/push, security penetration or operational rollback. No provider keys are required in this stage.
