# Master brief coverage after Stage 2

The complete master brief remains the product scope. This matrix separates implemented development interfaces from pending commercial capabilities. Detailed interactions are in stage-2-features.md.

| Area | Stage 2 evidence | Remaining gate |
| --- | --- | --- |
| Original branding/design | Preserved logo/tokens; shared React vectors and Compose drawings/themes | Licensed real catalogue imagery and broader accessibility/device review |
| Customer Android A–M | Compiled screens/navigation, local sessions/catalogue/search/basket/checkout/orders/profile/support | Genuine OTP/auth, server data, providers and device UI acceptance |
| Rider Android | Compiled registration/availability/offers/pickup/completion/history/earnings/profile | Real approval, assignment, tracking/contact, payouts and device validation |
| Customer website 16 pages | Shopping/account/orders/support/about/contact and draft policy routes | Authenticated backend, final policies and full browser/device matrix |
| Admin overview | Metrics/charts calculated from actual local synthetic records | Real database reports and secure role/store enforcement |
| Product/inventory management | Local creation/edit/price/MRP/stock/availability and category selection | Category/brand/supplier master CRUD, secure images and transactional stock |
| Orders/customers/delivery management | Order workflow, partner assignment/availability, read-only synthetic customers | Real customer accounts, dispatcher trust boundaries and database ownership |
| Marketing | Local campaign dates/occasions, coupon creation/validation | Targeted collections, performance and genuine opted-in notifications |
| Financial reporting | Derived delivered-product/order reports and development CSV | Verified receipts/refunds, costs/profit and payout ledger |
| Backend 24 modules | Stage 1 architecture/schema/contracts preserved; typed clients prepared | NestJS/PostgreSQL/worker implementation and complete contract tests |
| Database/migrations | 47-table SQL draft and reference seed preserved | Actual PostgreSQL migration/concurrency/backup evidence |
| Maps/addresses/zones | Local addresses, sample zone controls and clear placeholders | Real pin/search, validated boundaries, genuine routes/ETA and restricted keys |
| Business rules | Preserved tested integer-paise calculation; local interfaces and rule editor | Authoritative versioned server settings and verified tax treatment |
| Payments/UPI/COD/refunds | Explicit no-charge development checkout/completion | Merchant sandbox, verification/webhooks/refund limits and enabled methods |
| Notifications | Preference UI and placeholders; no message sent | OTP provider/FCM/device tests and transactional outbox |
| Festivals | Editable campaign dates and all requested occasion choices | Operational offer/eligibility approval and performance records |
| Security | Safe output/control boundaries, fail-closed adapters, no secrets, source gates | Real identity/RBAC, rate limits, upload security, privacy and penetration testing |
| QA | 42 Node, 12 Android unit and 38 actual browser assertions; both APKs/builds/signatures | Physical-device/integration/accessibility/security/load/recovery gates |
| Source/docs/ZIP/APKs | Full updated sources, wrapper/locks/notices, guides, reports, screenshots and debug APKs | Production release/AAB/signing/deployment approval |
| AI quality | No model/provider hidden behind the brand | Concrete evaluated use case plus cost/privacy/license decision |
| Optional wallet | Explicitly deferred | Separate ledger/business decision |

Campaign occasions: Diwali, Holi, Raksha Bandhan, Janmashtami, Navratri, Dussehra, Makar Sankranti, Maha Shivaratri, Ram Navami, Eid, Christmas and New Year. No festival date or delivery promise is hardcoded as a real offer.

No proprietary competitor source/screens/images are copied. There is no live order, payment, location, useful-model-quality, 1,000-orders/day capacity or production-readiness claim. Stage 1 historical records are retained under docs/history.
